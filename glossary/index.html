Glossary

Glossary and key terms

These definitions explain how core terms are used across the ASPIRE website. They are written for cross-domain readers and are intended to support shared understanding rather than serve as textbook definitions.

Core terms

Each entry is scoped to the language used on this site and linked project pages.

Digital Twin
On this site, a Digital Twin links data, models, and operational context so a real system can be observed, interpreted, and improved. The term is used across mobility, manufacturing, nursing, and agriculture rather than for a single sector.
DT lifecycle
The DT lifecycle refers to the recurring path from data collection to model integration, deployment, evaluation, and feedback. It emphasizes that the platform is refined continuously rather than built once and left unchanged.
Core Platform
The Core Platform is the shared research layer that coordinates data flows, models, services, and evaluation across the project. It is the common infrastructure used by all Domain Programs.
Domain Programs
Domain Programs are the four application areas in ASPIRE: Mobility, Manufacturing, Nursing, and Agriculture. Each program tests methods in context and returns evidence to the Core Platform.
Interoperability
Interoperability means that project components can exchange data and work together without requiring a one-off integration for every case. It matters when methods move across institutions, systems, and domains.
Orchestration
Orchestration refers to how the platform coordinates data handling, models, and services across the Digital Twin lifecycle. The term highlights management of connections between components, not only the behavior of one model.
Core services
Core services are reusable platform functions that can be shared across Domain Programs. They support repeated research and deployment work instead of forcing each domain to rebuild the same capabilities.
Work Package
A Work Package is one organized part of the project plan. In ASPIRE, Work Packages group management, scenarios and use cases, platform and Artificial Intelligence (AI) models, field trials, and dissemination.
Proof of Concept
A Proof of Concept (PoC) is a focused implementation or field-based test used to examine whether a method or service works in practice. In ASPIRE, PoCs also generate feedback for platform refinement.
Standardization
Standardization refers to making methods, interfaces, or processes consistent enough to be reused across settings. On this site, it usually appears as a downstream outcome of platform and field work.
Global Forum
The Global Forum is the project-wide venue for researchers, practitioners, and partner organizations to compare findings across domains. It supports shared review rather than domain-by-domain isolation.
Matching Workshop
The Matching Workshop brings early-career researchers together around shared themes, mentors, and possible collaboration paths. It is intended to help form joint work rather than function as a standalone showcase event.
Researcher Exchange
Researcher Exchange refers to activities that move researchers and working knowledge across institutions. It extends collaboration beyond meetings by linking people, methods, and field contexts.
Outputs
Outputs are the public-facing materials released through the project, including publications, reports, software, datasets, and related resources. The term is broader than publications alone.
Team and governance
Team and governance refers to the public view of project leadership, Work Package responsibility, domain leads, and Core Platform coordination. The site uses this term instead of mixing "people" and "team" labels.
